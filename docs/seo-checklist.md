# SEO: структура и проверка публикации

## Страницы

Аудитория: действующий малый и средний бизнес, стартапы и команды новых цифровых продуктов. Тексты раскрывают состав работы, исходные данные, результаты и ограничения. Цены, сроки, отзывы и достижения без подтверждения не публикуются.

| Раздел | Адрес | Задача страницы |
| --- | --- | --- |
| Услуги | `/services` | Выбор направления по задаче бизнеса |
| Веб-приложения | `/services/web-applications` | Личные кабинеты, рабочие системы и MVP |
| CRM и автоматизация | `/services/crm-automation` | Процессы, заявки, данные и интеграции |
| AI-решения | `/services/ai-solutions` | Сценарии, пилот, качество и ограничения AI |
| Этапы работы | `/process` | Общий порядок разработки |
| Аналитика | `/process/discovery` | Задача, пользователи и критерии результата |
| Требования | `/process/requirements` | Функции, MVP и приемка |
| Дизайн | `/process/ux-ui-design` | Пользовательские пути, экраны и состояния |
| Архитектура | `/process/architecture` | Модель данных, доступы и обмен |
| Разработка | `/process/development` | Реализация сценариев и промежуточные версии |
| Проверка | `/process/testing` | Покрытие, риски и решение о готовности |
| Запуск | `/process/launch` | Рабочее окружение и переход пользователей |
| Развитие | `/process/support` | Поддержка, обратная связь и следующие выпуски |

Каждая подробная страница доступна с главной, из своего раздела и по тематическим ссылкам. Страницы предварительно генерируются в HTML. У каждой есть собственные title, description, canonical, OpenGraph, H1 и хлебные крошки. Разметка Service используется на страницах услуг; она не обещает специального вида выдачи.

Исходники текстов: `src/shared/content/services.ts` и `src/shared/content/process.ts`. При содержательном изменении обновляйте `CONTENT_UPDATED_AT` в `src/shared/content/types.ts`: эта дата используется в sitemap и разметке страниц. Не меняйте дату только ради очередного деплоя.

Приём заявок сейчас отключён через `PROJECT_CONTACT_ENABLED`. Кнопки на новых страницах также неактивны. Статус в `public/llms.txt` нужно обновить, когда приём заявок возобновится.

## Изображения

Отдельные декоративные AI-иллюстрации для этих страниц не добавлены: их вклад в поисковый трафик не подтверждён. При появлении полезного материала добавляйте реальные примеры интерфейсов, схемы обмена данными или фрагменты проектных документов с разрешёнными к публикации данными. Условные примеры обозначайте как примеры, а не выполненные кейсы.

Для содержательных изображений нужны описательное имя файла, осмысленный alt, заданные размеры, адаптивная загрузка и оптимизированный формат. Декоративным изображениям оставляйте пустой alt. Не помещайте важные объяснения только внутрь изображения.

Общая OpenGraph-карточка приведена к текущим цветам сайта. Она служит превью при обмене ссылками и не является доказательством улучшения поисковых позиций.

## Локальная проверка

1. `npm run lint`
2. `npm run build`
3. `npm run start -- --port 3107`
4. В другом терминале: `SEO_BASE_URL=http://localhost:3107 npm run check:seo`

Проверка обходит все страницы из sitemap без выполнения JavaScript: статусы HTTP, уникальность метаданных, canonical, H1, JSON-LD, ссылки и якоря, исключение внутренней страницы, robots.txt, llms.txt и ответы 404.

В браузере дополнительно проверяйте главную, оба раздела и все подробные страницы на телефоне и компьютере: читаемость, переносы заголовков, отсутствие горизонтального скролла, переходы по карточкам, хлебным крошкам и меню.

## После публикации

1. Проверить `https://brobear.ru/robots.txt`, `/sitemap.xml` и `/llms.txt`. В sitemap должны быть главная, два раздела и одиннадцать подробных страниц. Ресурсы `/_next/` доступны роботу для отображения страниц; `/themes` имеет noindex и отсутствует в sitemap.
2. Проверить реальные canonical-адреса и отсутствие noindex на публичных страницах. Убедиться, что неверные адреса возвращают HTTP 404, а HTTP/www-варианты домена перенаправляются на выбранный HTTPS-домен.
3. Подтвердить сайт в Google Search Console и Яндекс Вебмастере. В проекте предусмотрены `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` и `NEXT_PUBLIC_YANDEX_VERIFICATION`; значения берутся из соответствующих кабинетов.
4. Отправить `/sitemap.xml` в обе системы. Проверить несколько новых URL через инструменты проверки страниц и запросить переобход там, где это доступно.
5. Проверить разметку хлебных крошек через Google Rich Results Test. Наличие разметки не гарантирует расширенный результат.
6. Проверить скорость и Core Web Vitals на опубликованном сайте. Локальная сборка подтверждает работоспособность, но не качество сети, хостинга или пользовательские показатели.
7. После индексации отслеживать показы, клики, CTR и запросы по каждой услуге. Оценивать страницы этапов как материалы, которые объясняют работу и помогают перейти к подходящему направлению. Уточнять тексты по реальным вопросам клиентов и запросам, а не добавлять дубли страниц.

Пока сервисы поиска не получили опубликованные URL, фактическое изменение позиций и трафика не измерено. Семантика страниц основана на текущих направлениях компании; частотность запросов отдельно не исследовалась.
